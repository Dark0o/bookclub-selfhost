# 📚 Project Blueprint: BookClub App

> **Historical document.** This is the original concept from before development started. Where it
> differs from `PRODUCT_DECISIONS.md` (e.g. `Book` is not a separate model; the book's title and
> author live on `Club`), `PRODUCT_DECISIONS.md` and `prisma/schema.prisma` are correct.

## 1. Vision and Purpose

The application allows users to form small, private reading clubs focused on one specific book. The goal is to transform passive reading into active, deep discussion through structured weekly phases and a question-valuation system.

## 2. User Roles

- **Admin (Owner):** The user who creates the club. They define the reading plan, invite members, exercise "Veto" power over questions, and archive the club.
- **Member:** A user who joins via an invite link. They can propose questions, vote, and participate in discussions.

## 3. Club Lifecycle

1. **DRAFT:** Admin sets up details (book, total pages/chapters, reading schedule).
2. **ACTIVE:** Reading is in progress. Weekly threads are unlocked sequentially.
3. **ARCHIVED:** The book is finished. The club remains as a "Digital Shelf" containing saved insights (Grand Library).

## 4. Reading Dynamics and Threads

- **Periodization:** Reading is divided into weeks (e.g., 4 weeks per book).
- **The Splitter:** Admin defines the range for each week (e.g., Week 1: pages 1-80, Week 2: 80-160, etc.).
- **Weekly Thread:** Each week has a dedicated space containing:
  - **Progress Goal:** Clearly defined section of the book to be read.
  - **Question Pool:** A "sandbox" for member-proposed questions.
  - **Discussion Area:** Deep-dive discussions organized by specific questions.

## 5. Question Pool & Engagement (Core Feature)

- **Proposal Phase:** Members post questions specific to the current reading section.
- **Upvoting:** Members vote for the most interesting/provocative questions.
- **Admin Veto:** The Admin can "pin" one question as mandatory/featured, regardless of vote count.
- **Threaded Answers:** Each selected question becomes a mini-thread (Reddit-style) to maintain discussion clarity.
- **Spoiler Safe:** All content (questions and answers) is blurred by default ("Click to Reveal") to protect those reading at a slower pace.

## 6. Grand Library (Archive)

- At the end of each week, the top 3-5 questions with the best answers are moved to the club's permanent archive.
- Upon completion, the user has a personalized "Insight Digest" – a collection of the group's best reflections on that book.

## 7. Technical Stack

- **Frontend:** Next.js 16 (App Router), Tailwind CSS, shadcn/ui.
- **Auth:** Better Auth (Email & Google login).
- **Database:** Supabase (PostgreSQL) + Prisma ORM.
- **Client State/Fetching:** TanStack Query (React Query) for optimistic updates and real-time interaction.
- **Invite System:** Unique token-based links (e.g., `/join/[token]`).

## 8. Database Schema Blueprint (Prisma)

> ⚠️ Work in progress — treat as a starting point, not a final schema. Subject to change as architecture decisions are made.

- `User`: id (cuid, auto-generated by Better Auth), email, name, image, emailVerified.
- `Club`: name, description, inviteCode, status (Enum: DRAFT, ACTIVE, ARCHIVED), bookId.
- `Book`: title, author, totalPages, totalChapters (optional).
- `ReadingPhase`: weekIndex, startUnit, endUnit, unlockDate.
- `Question`: content, phaseId, authorId, isPinned, upvotesCount, status (Enum: PROPOSED, APPROVED).
- `Answer`: content, questionId, authorId, parentId (for nested/recursive replies).
- `Vote`: userId, questionId (Unique composite key).

## 9. MVP Scope (v1)

**In scope:**

- Club creation and invite system
- Reading phases (The Splitter)
- Question Pool with upvoting and Admin Veto
- Spoiler Safe content display
- Basic club lifecycle (DRAFT → ACTIVE → ARCHIVED)

**Out of scope for v1:**

- Grand Library / Insight Digest
- Notifications
- Mobile app
- Public clubs / discovery
